# Fellowship

Use the user's actual repository and preserve its current execution boundary. Read [the shared protocol](references/protocol.md), then only the role you need: [Gandalf](references/roles/gandalf.md) (coordinator; plans, writes packets, verifies), [Frodo](references/roles/workers.md) (worker), [Aragorn](references/roles/aragorn.md) (independent review; applies the [Éowyn](references/roles/eowyn.md) UX lens), [Galadriel](references/roles/galadriel.md) (security). Templates: [task](references/templates/task.md), [checkpoint](references/templates/checkpoint.md); bugs: [debugging](references/debugging.md). The main assistant is Gandalf; use a separate coordinator agent only when handing over coordination. Spawn independent bounded workers when useful, with at most two coding workers and a separate strong Aragorn for implementation review.

For an enrolled project, use its pinned `.fellowship/pack` contract, `.fellowship/README.md`, existing task system, and current handoff. Before editing, check actual Git state. If it is not enrolled, onboard it as part of the authorized coding task using `python3 <this-skill>/scripts/install.py onboard --project <repo>`; preserve existing instructions and report ownership conflicts. For a newly authorized code project, prepare its directory and initialize Git first when needed, without replacing existing files. Starting a read-only conversation does not authorize modifying the repo or publishing it to GitHub. Small tasks proceed directly with an acceptance condition under the shared protocol; planning and delegation scale with the work.

Before dispatch, read [model routing](references/models.md). Native roles are generated from `models.json`: ordinary work uses the coder/economy profiles and independent review stays strong. Preserve the user's main-session selection. Every child/helper/reviewer/retry/fallback must use an allowed model other than Astra or Fable; set it explicitly when the parent uses either. If a model cannot launch, disclose the block without changing authentication or providers. An existing Pi/local worker is optional under the same ownership and review rules; no extra lane is required.

**Bedtime:** `python3 <this-skill>/scripts/fellowship.py bedtime --project <repo>`, stop new dispatch/integration, checkpoint rich next steps in the existing task/handoff, and interrupt reachable owned subagents through native controls. Leave review and merging for explicit resume. Read status with the helper. Registered sessions with unfinished tool calls or missing stop acknowledgments produce `stop-unconfirmed`; they are not safe to ignore. Application services and other projects are separate.

**Resume:** in a paused hooked chat, the user sends the standalone `resume fellowship` command (or supported `/fellowship resume`). Longer prose does not clear the flag, and an agent cannot self-resume through Bash; explain the required command if needed. The user may also run `python3 <this-skill>/scripts/fellowship.py resume --project <repo>` directly in their own terminal. After authorized resume, reconcile live owners, actual source state, current instructions and checkpoint. Do not automatically take over work from an unreachable owner.

**Compatibility:** Fellowship includes its own clarification, planning, debugging, testing, and small-change practices. No other skill or plugin is required. Other installed skills may supply relevant techniques inside this workflow. The approved packet is a dispatched worker's brief. Follow current user instructions and native policy when any skill disagrees. A persona never authorizes extra tools, publishing, or merge/deployment rights.

Hooks provide a cooperative local pause guard for enrolled sessions, not complete containment or remote shutdown. Existing sessions may need a new turn or restart to load them; Codex may require native hook trust. Never bypass that trust. Read [installation limits](INSTALLATION.md) before claiming runtime enforcement.
